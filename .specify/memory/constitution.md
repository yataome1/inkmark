# Inkmark 项目宪章 (Constitution)

版本: 1.3.0 | 批准日期: 2026-11-06 | 最近修订: 2026-11-10

本宪章约束 Inkmark 的所有规格、设计与实现。规格 (spec)、计划 (plan)、任务 (tasks) 与代码如与本宪章冲突，以本宪章为准。

## 核心原则

### I. 规格先行 (Spec First)
任何功能必须先在 `specs/<编号>-<名称>/spec.md` 中以用户故事 + 验收场景描述，经计划 (`plan.md`) 与任务分解 (`tasks.md`) 后再实现。代码变更必须能追溯到某个需求编号 (FR-xxx) 或任务编号 (Txxx)。

### II. 本地优先、离线可用
Inkmark 是本地工具：打开、编辑、保存、渲染（含数学公式、图表、代码高亮）不得依赖网络。所有渲染资源随安装包分发。不收集任何遥测数据。

### III. 所见即所得，Markdown 为唯一真相
编辑体验以“即时渲染”为默认（输入即渲染，光标所在处显示源码标记）。磁盘上保存的永远是纯 Markdown 文本，不写入任何私有格式；用户可随时切换到源码模式。

### IV. 不丢数据
任何可能丢弃未保存内容的操作（关闭窗口、打开其他文件、新建）必须先确认。保存采用写入临时文件后原子替换的方式。

### V. 安全默认
前端只能通过显式授权（Tauri capability）的命令与插件访问系统能力，按最小权限授予；不向前端整体开放文件系统，本地文件只按需授权到已打开文档所在目录。文档中的外部链接只能在系统浏览器中打开，窗口本身不得被导航离开应用页面。

### VI. 简单
只实现规格中列出的需求；不预留扩展点、不加未被要求的配置项。优先使用成熟库（Tauri、CodeMirror）而非自研。

### VII. 轻量
Inkmark 是小工具：安装包 ≤ 10MB，免安装版 ≤ 15MB，由 CI 检查。引入新依赖或新的随包资源时，须在 plan 中说明对体积的影响；只打包实际用到的资源。

## 技术约束
- 目标平台：Windows 10 / 11 x64，以 Windows 11 为主要测试环境；产物为 NSIS 安装包与免安装单文件 exe。
- 运行时：Tauri 2 + 系统 WebView2（后端 Rust，前端原生 JS，无前端框架；应用代码不经打包，第三方库在 vendor 阶段由 esbuild 打包）。
- 编辑内核：CodeMirror 6（编辑状态即 Markdown 原文，即时渲染由装饰实现）。

## 开发流程
1. `spec.md`：做什么、为什么（不含技术细节）。
2. `plan.md`：怎么做（架构、模块、IPC 契约）。
3. `tasks.md`：可执行、可勾选的任务清单，按用户故事分组。
4. 实现：按任务顺序实现，每完成一项勾选。
5. 验证：按 `spec.md` 的验收场景逐条手动/自动验证，结果记录在 `checklist.md`。

## 治理
修改本宪章须更新版本号（语义化版本）并说明原因。
