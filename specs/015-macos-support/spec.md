# 功能规格：macOS 版本

**特性分支**: `015-macos-support` | **创建日期**: 2026-11-14 | **状态**: 已批准
**输入**: 根据现有规格中的软件特性，做一个 macOS 版本的 Inkmark；技术框架可按 macOS 的特点选择。评估现有目标（如安装包 ≤ 10MB）在 macOS 上是否适用，以及仓库如何管理。可行性评估见 [research.md](research.md)。

<!-- 本规格只描述 macOS 版本“做什么”；功能本身沿用 001–014 的规格，不重复。 -->

## 范围

- macOS 版本提供 001–014 中已实现的全部功能，行为与 Windows 版一致；只在 macOS 的操作习惯与 Windows 不同的地方（快捷键、菜单、安装、打开文件的方式）按 macOS 习惯处理。
- Windows 版的功能、文件格式、设置项不因本规格改变。
- 不在范围内：iOS / iPadOS 版、Mac App Store 上架、iCloud 同步（图片文件夹可设到 iCloud 云盘，与设到其他同步盘相同）。

## 用户场景与测试

### 用户故事 1 —— 在 Mac 上安装并打开 Markdown 文件 (P1)

Mac 用户下载一个安装文件，拖进“应用程序”即可使用，并能像其他 Mac 应用一样用 Inkmark 打开 `.md` 文件。

**独立测试**：在一台没有开发工具的 Mac 上，从 Releases 下载安装文件，安装后从访达打开 `.md` 文件。

**验收场景**
1. **假设** 用户下载了 macOS 安装文件，**当** 打开它并把 Inkmark 拖进“应用程序”，**那么** 可以从启动台 / 访达启动 Inkmark，且不需要另外安装任何运行时。
2. **假设** 已安装 Inkmark，**当** 在访达中对 `.md` 文件选择“打开方式 → Inkmark”，或把文件拖到程序坞中的 Inkmark 图标上，**那么** 文件在 Inkmark 中打开；Inkmark 已在运行时在已有窗口中新开标签，不启动第二个实例。
3. **假设** 用户把 Inkmark 设为 `.md` 的默认打开方式，**当** 双击 `.md` 文件，**那么** 文件在 Inkmark 中打开。
4. **假设** 用户的 Mac 是 Apple 芯片或 Intel 芯片，**当** 安装同一个安装文件，**那么** 都能原生运行。
5. **假设** 首次打开下载的 Inkmark，**当** macOS 进行安全检查，**那么** 系统提示无法验证开发者（本版本不做 Apple 签名与公证）；用户按 README 与使用指南中写明的步骤，在“系统设置 → 隐私与安全性”中点“仍要打开”后即可正常使用，之后不再提示。

### 用户故事 2 —— 符合 Mac 习惯的快捷键与菜单 (P1)

Mac 用户按习惯使用 `⌘` 快捷键和屏幕顶部的菜单栏，不需要记 Windows 的按键。

**独立测试**：在 macOS 上逐项按 `F1` 快捷键列表中的快捷键，并检查菜单栏。

**验收场景**
1. **假设** 在 macOS 上，**当** 按 Windows 版中以 `Ctrl` 开头的快捷键对应的 `⌘` 组合（如 `⌘S` 保存、`⌘/` 源代码模式、`⌘W` 关闭标签），**那么** 效果与 Windows 版相同。
2. **假设** 在 macOS 上，**当** 打开快捷键列表、菜单或右键菜单，**那么** 显示的是 macOS 的按键符号（`⌘` `⌥` `⇧` `⌃`），且与实际生效的快捷键一致。
3. **假设** 在 macOS 上，**当** 查看屏幕顶部菜单栏，**那么** 第一个菜单是“Inkmark”，包含“关于 Inkmark”“设置…”（若有）“隐藏”“退出 Inkmark（`⌘Q`）”；“窗口”菜单包含最小化、缩放；全屏使用 macOS 的全屏（`⌃⌘F`）。
4. **假设** 有未保存的修改，**当** 按 `⌘Q` 退出或关闭窗口，**那么** 与 Windows 版一样先询问（宪章 IV）。
5. **假设** 在 macOS 上，**当** 按系统级快捷键（如 `⌘H` 隐藏、`⌘M` 最小化、`⌘`` ` 切换窗口），**那么** 行为与其他 Mac 应用相同，不被 Inkmark 占用。

### 用户故事 3 —— 功能与 Windows 版一致 (P1)

已有功能在 macOS 上都能用，用户在两个系统之间切换时不需要重新学习。

**独立测试**：在 macOS 上按 001–014 的 `checklist.md` 逐项验证（只与 Windows 相关的项除外，见“边界情况”）。

**验收场景**
1. **假设** 在 macOS 上，**当** 执行 001–014 checklist 中的 P1 场景，**那么** 全部通过。
2. **假设** 在 Windows 上编辑过的文档（含图片文件夹中的图片），**当** 在 Mac 上打开，**那么** 内容与图片都正常显示；在 Mac 上保存后回到 Windows 打开，同样正常。
3. **假设** 在 macOS 上，**当** 导出 PDF，**那么** 结果与 Windows 版一致（分页、公式、图表、代码高亮）。
4. **假设** 在 macOS 上，**当** 对图片右键“复制图片文件”，**那么** 可以在访达中粘贴出该文件。
5. **假设** 系统切换浅色 / 深色外观，**当** Inkmark 主题为“跟随系统”，**那么** 随之切换。

### 边界情况

- 只属于 Windows 的内容在 macOS 上不出现：免安装 exe、WebView2 运行时、NSIS 安装钩子、“关于”中的 Windows 版本号（改为显示 macOS 版本）。
- 关闭最后一个窗口时：按 Mac 习惯，程序不退出、保留在程序坞中；再次点击程序坞图标或从访达打开文件时重新显示窗口（无文档时为起始页）。`⌘Q` 才退出程序。
- 路径：文档中写入的相对图片路径一律使用 `/`，两个系统都能读取；Windows 的盘符路径在 Mac 上打开时按“找不到图片”处理，不报错。
- 文件名大小写：macOS 默认不区分大小写但保留大小写，与 Windows 相同；不额外处理区分大小写的磁盘。

## 需求

### 功能需求

- **FR-1501** 系统必须在 macOS 上提供 001–014 中已实现的全部功能；与 Windows 的差异只限于本规格列出的项。
- **FR-1502** 系统必须以 macOS 的拖放安装方式分发，单个安装文件同时支持 Apple 芯片与 Intel 芯片。
- **FR-1503** 系统必须能从访达的“打开方式”、默认打开方式、拖到程序坞图标打开 `.md` `.markdown` `.mdown` 文件；已运行时在已有窗口中打开。
- **FR-1504** macOS 上所有以 `Ctrl` 开头的快捷键改为对应的 `⌘`；快捷键列表、菜单、右键菜单显示 macOS 符号。不能直接映射的快捷键（如 `Ctrl+Tab` 切换标签、`F` 功能键）在 plan 中逐项确定。
- **FR-1505** 系统必须提供符合 macOS 习惯的菜单栏（应用菜单、窗口菜单），不占用系统级快捷键。
- **FR-1508** macOS 上关闭最后一个窗口时程序不退出；点击程序坞图标或打开文件时重新显示窗口；`⌘Q` 与程序坞“退出”在有未保存修改时先确认（宪章 IV）。
- **FR-1506** 设置、最近文件、收藏、图片文件夹默认位置存放在 macOS 的标准位置；macOS 与 Windows 的设置互不影响。
- **FR-1507** 使用指南与 README 增加 macOS 的安装与快捷键说明。

### 非功能需求

- **NFR-1501** 体积：macOS 安装文件（`.dmg`）≤ 10MB（与 Windows 安装包相同；research.md R2 实测通用版原型 7.32MB），由 CI 检查（宪章 VII）。
- **NFR-1502** 系统要求：macOS 12 Monterey 及以上（Apple 芯片与 Intel 芯片）。
- **NFR-1503** 离线、无遥测、不丢数据、安全默认等宪章原则在 macOS 上同样适用。
- **NFR-1504** Windows 版的体积、行为不受影响；两个平台的 CI 都必须通过。

## 成功标准

- **SC-1501** 在 Apple 芯片与 Intel 芯片的 Mac 上各完成一次全部 P1 checklist，全部通过。
- **SC-1502** 同一版本号同时发布 Windows 与 macOS 安装文件。

## 澄清与假设

- 假设 Windows 与 macOS 共用同一套功能规格、同一个版本号、同一个仓库（理由见 research.md）。
- 宪章“技术约束”的目标平台已在本规格批准时修订为 Windows 与 macOS（宪章 1.4.0）。
- 澄清结果（2026-11-14）：本版本不做签名与公证；关闭最后一个窗口按 Mac 习惯保留程序；最低 macOS 12；`.dmg` ≤ 10MB。
- 不签名意味着首次打开需要用户手动放行（见用户故事 1 场景 5）；以后购买 Apple 开发者账号后另开规格增加签名与公证。
