# 功能规格：表格单元格行内代码中的 `\|` 不再丢失

**特性分支**: `fix/table-code-pipe-escape` | **创建日期**: 2026-11-06 | **状态**: 已实现，待评审
**输入**: 规格 003 原型中发现的缺陷 D-3：表格单元格的行内代码里含转义竖线（如 `` `a \| b` ``）时，保存后反斜杠丢失，表格被拆列。决定先作为 0.2.1 单独修复。

## 用户场景与测试

### 用户故事 1 —— 含 `\|` 的表格保存后不损坏 (P1)
用户打开、编辑并保存含 `` `a \| b` `` 单元格的文档，表格结构与内容保持不变。

**独立测试**：打开含该表格的文档，在表格中输入文字、复制表格、切换源代码模式、保存后重新打开，对比 Markdown 与列数。

**验收场景**
1. **假设** 文档有单元格 `` `x \| y` ``，**当** 不做修改直接保存，**那么** 文件中仍是 `` `x \| y` ``，重新打开后该行列数不变。
2. **假设** 同上，**当** 在该表格任一单元格中输入文字，**那么** 表格立即保持原有列数，单元格内容不被拆开、不丢列。
3. **假设** 同上，**当** 切换到源代码模式（`Ctrl+/`），**那么** 源代码中显示 `` `x \| y` ``。
4. **假设** 同上，**当** 选中表格复制并粘贴为纯文本，**那么** 文本中是 `` `x \| y` ``。
5. **假设** 单元格是 `` `m \\| n` `` 或公式 `$p \| q$`，**当** 保存，**那么** 原样保留。
6. **假设** 表格之外的行内代码 `` `p \| q` ``，**当** 保存，**那么** 原样保留（与修复前一致）。

### 边界情况
- 一个单元格中有多个行内代码、行内代码含多个 `|`：全部保留转义。
- 引用块、列表中的表格：同样适用。
- 行内代码在渲染界面中显示为 `x | y`（不显示反斜杠），与 GitHub 一致。

## 需求

### 功能需求
- **FR-401** 表格单元格中行内代码里的每个 `|`，在转为 Markdown 时必须写成 `\|`；适用于保存、源代码模式、复制和编辑中的即时渲染。
- **FR-402** 表格外的行内代码、公式、代码块的转换结果不得改变。

### 非功能需求
- **NFR-401** 不增加可感知的输入延迟：约 1000 行的文档中，每次转换额外耗时 < 2ms。

## 成功标准
- **SC-401** 验收场景 1–6 全部通过；`npm test` 覆盖 FR-401、FR-402。

## 澄清与假设
- 原因在编辑器内核 Lute：渲染表格时按 GFM 把 `\|` 还原为 `|`，转回 Markdown 时却没有重新转义。内核未修复前由本应用补齐转义；升级 Vditor 时须复查（`checklist.md`）。
- 不在范围内：单元格中 `z \| w`（非代码）转换时 `\|` 前的空格被去掉（`z\| w`）。这是内核的另一处小问题，不破坏表格结构，另行记录。
