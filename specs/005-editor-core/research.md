# 调研：编辑器内核评估

**日期**: 2026-11-06 | **规格**: [spec.md](spec.md)

## 方法
- 原型 A：CodeMirror 6（`@codemirror/view` 6.43.15、`lang-markdown` 6.5.2）+ 自写即时预览：隐藏 `#`、`**`、`` ` `` 等标记（光标进入时显示）、标题样式、图片、行内/块公式（KaTeX）、Mermaid、表格（可编辑单元格），撤销用 `@codemirror/commands` 的 `history`。约 250 行。
- 原型 B：Milkdown Crepe 7.23.0 默认功能 + Mermaid 预览（`renderPreview`），撤销用 ProseMirror `history`。
- 基线：Inkmark 0.2.1（Vditor 3.11.2），release 构建，CDP 测量。
- 文档：`resources/samples/demo.md`（75 行）与长文档（demo × 15，1141 行，15 个 Mermaid 图、15 个表格、30 个公式）。
- 原型用 esbuild 打包，在 Chromium（与 WebView2 同内核）中运行；原型代码不入库（FR-501）。

## 对比

| 撤销（长文档，输入一字后） | 约 99ms，**整篇替换 `innerHTML` 并重新渲染**（4.0.1 相同） | **5.6ms**，可见的图表、公式、表格 4/4 不动 | 5.5ms，可见块 45/45 不动 |
| 重做 | 同撤销 | 4.6ms，块不动 | 7.2ms，块不动 |
| 载入长文档 | 整篇设置约 146ms | **81ms**（只渲染可视区域） | 798ms（全部渲染） |
| 点击图表 | 源码在上方展开，内容跳动（需按帧补偿，规格 003 US4） | 在同一次更新内把块顶滚回原位：块顶 140px → 源码首行 140px，之后 135px（偏差来自原型的内边距） | 代码块始终同时显示源码与预览，不展开，无跳动；但不是 Typora 式交互 |
| 不编辑直接取出 Markdown（demo.md） | **6 处改写**：`[TOC]`→`[toc]`、`[x]`→`[X]` 并多一个空格、表格前多空行、表格列重新补齐 | **逐字相同**（仅换行符统一为 LF，可按原文件换行符写回） | **7 处改写**：`[TOC]`→`\[TOC]`（含义改变）、`-`→`*`、表格补齐错位、**图片说明文字被替换为 `1.00`（丢失）**、脚注链接加 `<>`、`---`→`***` |

| 维护状态 | 活跃 | 活跃（2026-10） | 活跃（2026-10） |

## 结论
**推荐 A：CodeMirror 6。**

- **撤销、点击、表格三个问题同时解决**：编辑对象就是 Markdown 原文，撤销只重绘改动的部分；点击锚定可在编辑器自身的更新周期内完成，无需按帧补偿；表格操作天然只改该表格的文字。
- **不改写用户文件**（宪章 III、IV）：唯一没有改动原文的方案。Vditor 与 Milkdown 打开即保存都会改写文件，Milkdown 还会丢失图片说明文字，规格 004 那类转换缺陷也不会再出现。
- **更轻**（宪章 VII）：内核从 4.29MB 降到约 0.5MB，安装包预计变小。
- **长文档更快**：只渲染可视区域。

不选 B：保存时改写文件且丢内容，不满足宪章 III；标记始终隐藏，不是 Typora 式体验；载入最慢。

## 替换的代价与风险
- **工作量大**：即时预览需自行实现。原型已覆盖标题、强调、行内代码、图片、公式、Mermaid、表格；还需列表与任务列表、引用、链接（Ctrl+单击）、脚注、`[TOC]`、分隔线、HTML、代码高亮、粘贴/拖入图片、专注与打字机模式、查找替换（可用 `@codemirror/search`）、HTML/PDF 导出（Vditor 的 `preview` 需替换，例如 markdown-it）。源代码模式只需关闭预览装饰。
- **中文输入法**：CodeMirror 6 的输入法组合处理需在 WebView2 中实测（含候选词位置、组合中按 Esc）。
- **构建方式变化**：需在 `npm run vendor` 中用 esbuild 把 CodeMirror 打包为本地资源（新增开发依赖）。`src/` 仍为原生 JS，但 AGENTS.md 中“无打包器”需修订，宪章技术约束需修订（MINOR）。
- **规格 003 的影响**：用户故事 1（表格）、4（不跳动）应在新内核上实现；用户故事 2（分割线）、3（收藏夹）与内核无关，可照常进行。
- **迁移方式**：新内核整体替换，不并存两个内核；通过 002 与 003 的验收清单回归。
