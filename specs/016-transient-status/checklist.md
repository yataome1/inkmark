# 验收检查：状态栏的一次性提示自动消失

**版本**: 分支 `016-transient-status`（基于 `main` aea5b90，含 015 macOS 版本） | **日期**: 2026-11-15 | **环境**: macOS 15（Apple 芯片），开发版（`npm start`）

“手动”指用户在开发版中实际操作；判定依据是临时加入的状态栏记录（每次变化记下时间戳与内容，验证后已删除，未提交）。

| 场景 | 方式 | 结果 | 备注 |
|---|---|---|---|
| US1-1 提示约 4 秒后消失 | 手动 + 单元测试 | ✅ | “已复制图片”“已复制图片文件”“已复制图片地址”“已导出：…”“使用指南为只读…”均在 4.00 秒后清空；`status-message.test.js` |
| US1-2 新提示替换并重新计时 | 手动 + 单元测试 | ✅ | “已复制图片”后 2.9 秒出现“已复制图片文件”，从新提示起 4.00 秒清空 |
| US1-3 各类操作结果都会消失 | 手动 + 代码审查 | ✅ | 实测复制图片三项、导出 HTML、只读提示；其余（全部保存、导出可分享副本、收入图片、图片文件夹、跳过文件、右键编辑菜单）经代码确认都走 `showStatus` |
| US1-4 “操作失败：…”同样消失 | 代码审查 | ✅ | `ImageMenu`、`EditMenu` 的失败提示走同一 `onStatus` → `showStatus` |
| US2-1 持续状态与提示同时显示 | 手动 | ✅ | 使用指南 + 专注：“只读 · 专注”与“使用指南为只读…”并存，提示消失后“只读 · 专注”仍在 |
| US2-2 切换模式、标签不清除提示 | 手动 | ✅ | 提示显示中切换标签（“只读”消失）、开启打字机（变为“只读 · 专注 · 打字机”），提示均保留并按原计时消失 |
| US2-3 只读的使用指南上按 ⌘S | 手动 | ✅ | |
| 边界：无持续状态时不留空隙 | 手动 | ✅ | 无持续状态时 `#status-flags` 为 `display: none` |
| 边界：长路径与窄窗口 | 手动 | ✅ | 首次实测发现窄窗口下状态栏变为两到三行高（“即时渲染”被逐字折行，❌），改为整条状态栏不换行后复验：提示显示期间窗口在 441–940px 间拖动，状态栏始终一行高（24px），“即时渲染”与字数统计完整、不出界，导出路径以省略号截断，`title` 为完整文字，4 秒后照常消失 |
