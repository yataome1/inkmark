# 功能规格：“关于”与帮助菜单

**特性分支**: `009-about-dialog` | **创建日期**: 2026-11-09 | **状态**: 已批准
**输入**: 按开源软件的最佳实践完善帮助中的“关于”。版权署名 zhangmian；问题反馈统一走 GitHub Issue；不放赞助链接；获取新版只打开 Releases 页面；仓库暂不公开。

## 用户场景与测试

### 用户故事 1 —— 了解软件并提供版本信息 (P1)

用户想知道当前版本，或在反馈问题时准确提供运行环境。

**独立测试**：打开“关于”，核对各项信息，复制版本信息并粘贴到文本编辑器。

**验收场景**

1. **当** 选择“帮助 → 关于 Inkmark”，**那么** 显示应用内对话框：图标、名称、一句话简介、版本号、提交号、构建日期、Tauri 版本、WebView2 版本、Windows 版本。
2. **当** 单击“复制版本信息”，**那么** 上述版本信息以多行纯文本写入剪贴板，按钮短暂显示“已复制”。
3. **当** 按 `Esc`、单击“关闭”或单击对话框外部，**那么** 对话框关闭，焦点回到打开前的位置，文档内容和未保存状态不受影响。
4. **当** 对话框打开，**那么** 键盘焦点限制在对话框内，`Tab` 可到达所有操作，配色跟随浅色、深色主题。
5. **当** 查看对话框，**那么** 显示隐私说明：“完全离线，无遥测，不收集任何数据”。

### 用户故事 2 —— 许可证与第三方声明 (P1)

用户和再分发者可以离线查看本软件的许可证，以及所含开源组件的版权和许可信息。

**独立测试**：断网后打开许可证全文和第三方声明，核对组件列表与实际依赖一致。

**验收场景**

1. **当** 查看“关于”，**那么** 显示 `Copyright (c) 2026 zhangmian` 和 MIT 许可证，可查看许可证全文。
2. **当** 打开“第三方声明”，**那么** 列出随软件分发的全部开源组件（前端与 Rust）的名称、版本、许可证，并可展开查看版权与许可原文。
3. **假设** 没有网络，**当** 查看上述内容，**那么** 全部可用。
4. **假设** 依赖发生变化，**当** 构建，**那么** 第三方声明随之更新；存在缺少许可信息的组件时构建检查失败。
5. **当** 查看“关于”，**那么** 显示“设计灵感来自 Typora。Inkmark 是独立的开源项目，与 Typora 无关。”

### 用户故事 3 —— 帮助入口 (P2)

用户可以从“帮助”菜单和“关于”找到项目资源。

**独立测试**：逐项单击“帮助”菜单和“关于”中的链接，确认打开的地址。

**验收场景**

1. **当** 查看“帮助”菜单，**那么** 依次为：Markdown 示例文档、键盘快捷键（`F1`）、更新日志、报告问题、获取新版、项目主页、第三方声明、关于 Inkmark。
2. **当** 单击“获取新版”，**那么** 只在系统浏览器中打开 GitHub Releases 页面，应用不进行任何联网检查或下载。
3. **当** 单击“报告问题”，**那么** 在系统浏览器中打开 GitHub Issue 页面。
4. **当** 单击“更新日志”“项目主页”，**那么** 在系统浏览器中分别打开仓库的 `CHANGELOG.md` 和仓库主页。
5. **当** 单击“关于”中的项目主页、更新日志、报告问题、获取新版，**那么** 行为与对应菜单项相同。

### 用户故事 4 —— 查阅键盘快捷键 (P2)

用户可以在一处查到所有快捷键，不用逐个翻菜单。

**独立测试**：按 `F1` 打开列表，与实际可用的快捷键逐项核对，断网和起始页下各打开一次。

**验收场景**

1. **当** 按 `F1` 或选择“帮助 → 键盘快捷键”，**那么** 显示应用内快捷键列表，按文件、标签、编辑、段落、格式、表格、视图分组，每项显示操作名称和按键。
2. **当** 查看列表，**那么** 包含所有快捷键，包括只在特定位置生效的表格快捷键，以及不在菜单中的撤销、重做等；只在特定位置生效的项注明位置。
3. **当** 按 `Esc`、单击“关闭”或单击列表外部，**那么** 列表关闭，焦点回到打开前的位置。
4. **假设** 窗口较小，**当** 查看列表，**那么** 分组内容可滚动，由双栏变为单栏。
5. **假设** 当前是起始页，**当** 按 `F1`，**那么** 列表正常打开。

### 边界情况

- WebView2 或 Windows 版本读取失败：该项显示“未知”，其余信息正常。
- 从起始页打开“关于”：可用，关闭后回到起始页的原焦点。
- 有未保存修改时打开或关闭“关于”：不提示保存。
- 窗口较小时：内容可滚动，操作按钮始终可达。
- 重复选择“关于”：不打开第二个对话框。

## 需求

### 功能需求

- **FR-901** “关于”必须是应用内对话框，显示用户故事 1 列出的软件与运行环境信息。
- **FR-902** 必须提供“复制版本信息”，内容足以直接粘贴到 Issue。
- **FR-903** 版权署名必须统一为 `zhangmian`：“关于”、`LICENSE` 与项目元数据一致。
- **FR-904** 必须随软件分发并可离线查看 MIT 许可证全文和第三方声明。
- **FR-905** 第三方声明必须在构建时由实际依赖生成，覆盖前端随包组件与 Rust 依赖；CI 必须在缺少许可信息时失败。
- **FR-906** “帮助”菜单和“关于”必须提供用户故事 3 的入口；链接只由用户单击触发，只在系统浏览器中打开，且仅限 `https://github.com/yataome1/inkmark` 下的地址。
- **FR-907** 问题反馈入口只有 GitHub Issue，界面不显示邮箱，不提供赞助链接。
- **FR-908** 对话框必须可完全用键盘操作，具备对话框角色和可访问名称，界面文本使用简体中文。
- **FR-909** 必须提供键盘快捷键列表（`F1`），内容与实际快捷键一致；出现新增快捷键未写入列表时，自动测试必须失败。

### 非功能需求

- **NFR-901** 应用不得因本功能发起任何自动网络请求（宪章 II）；不新增更新检查。
- **NFR-902** 安装包 ≤ 10MB、免安装版 ≤ 15MB（宪章 VII）。

### 关键实体

- **版本信息**：版本号、提交号、构建日期、Tauri、WebView2、Windows 版本。
- **第三方组件**：名称、版本、许可证、版权与许可原文。

## 成功标准

- **SC-001** 用户故事 1–4 的验收场景全部通过。
- **SC-002** 第三方声明覆盖发布包内的全部开源组件，CI 可防止遗漏。

## 澄清与假设

- 仓库暂不公开。为满足“问题走 GitHub Issue”“获取新版打开 Releases”，这些链接照常显示；仓库私有期间，没有访问权限的人打开后会看到 GitHub 的 404 页面。仓库公开后无需改动。
- 不在本规格范围：应用内检查更新、自动更新、赞助入口、显示联系邮箱、快捷键的搜索和自定义。
